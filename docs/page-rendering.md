# Rendering a complete page

`render_page` returns a Markdown document with YAML frontmatter. It does not write
files or enable the generation command or HTTP middleware.

```python
from wagtail_markdown_agents.export.policy import ExportPolicy
from wagtail_markdown_agents.rendering import PageRenderError, render_page

if ExportPolicy().is_eligible(page):
    markdown = render_page(page)
```

It reloads the page and reconstructs its live revision, including when the supplied
instance is a draft or stale. A live page with no published revision is rejected:
publish a revision first. The writer must run after commit and recheck current
eligibility/publication state before publishing an artefact; rendering alone does
not protect against concurrent restriction or unpublish operations.

## Field selection and errors

By default every StreamField and RichTextField renders in model definition order.
Use the exact model's label to select fields and order explicitly:

```python
WAGTAIL_MARKDOWN_AGENTS = {
    "PAGE_FIELDS": {"myapp.ContentPage": ["intro", "body"]},
}
```

Other page types still auto-detect their fields. An explicit empty list selects
none. Inherited fields are selectable; configurations apply to the concrete model,
not automatically to its subclasses. Invalid model labels, missing or duplicate
names, and fields of other types raise `ImproperlyConfigured`. Scalar fields,
relationships and arbitrary properties are never extracted automatically.

v0.1 requires a StreamField somewhere on the page model. A rich-text-only page and
a Wagtail form page are unsupported; a form's intro cannot stand in for its form.
`PageRenderError` exposes `page_id` and `reason` for command diagnostics:

| Reason | Meaning |
| --- | --- |
| `unpublished_page` | Unsaved/deleted/not live, or no live revision |
| `unsupported_page` | No StreamField, or a Wagtail form page |
| `empty_body` | Selected fields, hooks and supplied navigation produced no content |

These errors must not create a successful export record or discovery listing.
Configuration, conversion and hook failures propagate, preserving their cause.

## Project-owned hero content

Register `markdown_post_render` in your project's `wagtail_hooks.py`. It receives
only the selected field body; the generated heading and supplied navigation follow
the hook. The same context is shared with conversion and frontmatter hooks and
contains the published `page`, explicit/inferred `site`, `locale`, and site-bound
`settings` when `wagtail.contrib.settings` is installed. There is no request.

```python
from wagtail import hooks
from wagtail.blocks import RichTextBlock
from wagtail_markdown_agents.rendering.blocks import render_block
from .models import ContentPage


@hooks.register("markdown_post_render")
def add_hero(markdown, page, context):
    if not isinstance(page, ContentPage):
        return None
    context["heading"] = page.hero_headline or page.title
    hero = render_block(RichTextBlock(), page.hero_copy, context)
    return "\n\n".join(part for part in [hero, markdown] if part.strip())
```

Exclude `hero_copy` from `PAGE_FIELDS` when rendering it in the hook, as above, so
it appears once. Hooks return replacement Markdown or `None` to retain the previous
result, and run in Wagtail hook order. Other return types are errors. Set
`context["heading"] = None` to suppress the generated H1 when the authored body
already supplies one. Heading text is escaped; body headings are left as authored.
Changing the heading does not change the frontmatter title.

The fuller example in `sandbox/testapp/page_markdown.py` includes a labelled CTA
to an eligible page and omits the decorative hero image. Its exact output is pinned
by `tests/golden/page.md`; this is a synthetic example, not 350.org sign-off. For a
meaningful hero image, a project can explicitly use the existing image renderer:

```python
from wagtail.images.blocks import ImageChooserBlock

image_markdown = render_block(ImageChooserBlock(), page.hero_image, context)
```

Only include media that carries public content. Use the published page passed into
the hook, rather than fetching its latest revision.

## Navigation and remaining integration

`render_page(page, navigation=rendered_navigation)` appends supplied Markdown once
after the authored body. The index generator (#20) owns producing that navigation
and choosing whether a page already has an authored listing; assembly never removes
authored content by matching text. No child listing is generated by `render_page`
itself. The
[index generator](indexes.md) builds checked navigation and supplies it to assembly;
its navigation hook can explicitly suppress a duplicate authored listing. The
`root_index=True` assembly flag adds the package `OKF_VERSION` to frontmatter.

Implemented: ordered fields, published revision selection, block/conversion hooks,
page hook, heading control, frontmatter hooks, internal links and serialisation.

Storage/publication is available through the [writer API](storage-writer.md) (#19).
[Internal-link rewriting](internal-links.md) (#14) processes the complete body after
page hooks and navigation, before frontmatter is attached. It uses current owned
[public export URLs](public-export-routes.md) (#72), preserving canonical metadata.
Ungenerated or unavailable targets retain their HTML links. Generated navigation
is available through the [index API](indexes.md) (#20); command diagnostics (#24)
and content negotiation remain planned.
